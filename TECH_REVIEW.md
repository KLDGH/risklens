# RiskLens — Architecture and Implementation Reference

**Status:** Reference document. Describes how the system is built, what choices were made, and where the architectural seams lie.
**Audience:** Engineers and quants who want to understand the implementation in detail rather than read the user-facing FAQ.
**Scope:** Data model, computation pipeline, frontend architecture, quantitative methods, operational profile, scalability characteristics, and known limitations.

---

## 1. What this system actually is

RiskLens is a static-site risk dashboard with a batch-computed data layer. The user-facing surface is a single-page React application; the data layer is a single JSON document regenerated by a daily Python batch job. There is no application server, no live database, no message queue, and no cache between the daily compute and the rendered UI. This is intentional and constrains every other architectural choice.

The user-facing surface is organized into **five top-level tabs**:

1. **Summary** — exception-first view across all portfolios: active risk against a tolerance band per mandate type, beta, largest stress shortfall vs benchmark, VaR model check, and an exceptions list with owner and next step. Rows click through to the portfolio.
2. **Positioning** — ex-ante active risk, beta, and growth ↔ value from an 8-factor risk model, each beside its realized value; active factor exposures; AI and semis exposure; factor risk decomposition and risk-change attribution. Responds to the portfolio toggle.
3. **Extreme Risk** — per-asset and per-portfolio VaR/ES (five models), risk trajectory, and out-of-sample backtests. Responds to the portfolio toggle.
4. **Stress** — historical crisis replays and hypothetical scenarios with adjustable assumptions. Responds to the portfolio toggle.
5. **Market Context** — portfolio-independent reference charts (S&P 500 history, cross-asset and stock-bond correlation, intraday SPY-TLT correlation).

Three further views are **built but hidden from navigation**: Performance & Skill (risk-adjusted return, regime alpha, skill vs luck), Sector Spotlight (single sector-ETF deep-dive with anomaly detectors), and an Optimizer. Their data is still computed and their components are intact; re-adding an entry to `TABS` and `VALID_TABS` in `App.jsx` restores each. They were hidden to keep the dashboard focused on extreme risk rather than manager evaluation or single-asset research.

**Seven portfolio modes** are visible (`backend/config/portfolios.yaml`; order there is display order):

| Mode | Construction | Benchmark |
|---|---|---|
| `hypothetical` | Sample 60/40+: illustrative 60/30/8/2 mix from 14 asset-class ETFs | 60/40 ACWI / AGG |
| `aor` | iShares Core 60/40 (AOR) via its underlying ETFs; AOR NAV as reference | 60/40 ACWI / AGG |
| `tdf_2055` | Vanguard Target 2055 (VFFVX) via its 4 index funds | 90/10 ACWI / AGG |
| `cg_2035` | American Funds Target 2035 (AAFTX) via its underlying funds | 65/35 ACWI / AGG |
| `cggo_active` | CGGO look-through: top 25 disclosed holdings, re-normalized; CGGO NAV reference row | MSCI ACWI |
| `ica_active` | ICA look-through (AIVSX): top 25 from the quarterly disclosure | S&P 500 |
| `npf_active` | New Perspective look-through (R-6, RNPGX): top 25 from the quarterly disclosure | MSCI ACWI |

A `dwld_active` mode (Davis Select Worldwide ETF) is configured with `visible: false`.

The same pipeline runs once per mode and emits a unified JSON keyed by mode identifier; the frontend toggle swaps which mode's data drives the portfolio-aware tabs without re-fetching. The Summary tab reads every mode at once.

## 2. Stack and dependencies

**Backend (Python 3.10+; CI runs 3.11):** `pandas`, `numpy`, `scipy`, `arch` (GARCH MLE — the only non-from-scratch piece of the methodology), `yfinance` (Yahoo Finance adapter), `PyYAML` (configuration), `openpyxl` (xlsx parsing for sponsor holdings files, dev-only — CI reads the preprocessed JSON, never the source files).

**Frontend:** React 18 + Vite + Recharts. Plain CSS with a token layer for light and dark themes. Component-local state, no global store. ~760 KB JS bundle, ~220 KB gzipped.

**Hosting:** GitHub Pages via GitHub Actions (Node 22 for the build). Daily cron at 06:30 UTC on weekdays.

**External free data sources:**
- Yahoo Finance via yfinance — daily EOD adjusted prices + 5m/15m intraday for the last 60 days.
- Ken French Data Library — daily Fama-French 5 factors + Momentum, public.
- Sponsor holdings disclosures — Capital Group ETF daily-holdings xlsx; Capital Group mutual-fund quarterly portfolio disclosure (Word). Preprocessed locally into committed JSON.

The dependency footprint is intentionally small. Each library was added because it solves a specific problem the from-scratch alternative would solve worse: `arch` because reimplementing GARCH MLE with convergence handling is a multi-week project that produces inferior code; `yfinance` because building a Yahoo scraper is brittle; Recharts because it ships SVG charts with minimal code; `openpyxl` because writing an xlsx parser is silly when there's one trustworthy library. The Word disclosure is parsed with the standard library (`zipfile` + `xml.etree`). Everything else (HS, EWMA, EVT, Hill, Kupiec, Christoffersen, Component VaR, the ex-ante factor model, factor risk decomposition, scenario aggregation, intraday correlation, QMLE polarization, Page CUSUM, FF regression, OLS via `numpy.linalg.lstsq`) is implemented from first principles.

## 3. Architecture and data flow

Daily flow: GitHub Actions runner spins up Ubuntu, installs Python 3.11 + Node 22, runs `pip install -r backend/requirements.lock.txt`, executes `python backend/run.py` (fetches market data, computes all metrics, writes the JSON), runs `npm install && npm run build` in `frontend/`, deploys the static bundle to GitHub Pages. The Python compute runs about 5–7 minutes with the GARCH backtest cache in place.

The frontend issues one fetch to `data/risk_output.json` on load and renders the entire dashboard from the resulting object. No subsequent network calls during normal operation. `App` holds the active tab and the portfolio mode in local state (both mirrored to the URL as `?tab=` and `?portfolio=`); each section component receives the relevant JSON slice as props.

The Python batch is a single sequential pipeline:

0. **Configuration** — load and validate `portfolios.yaml`, `scenarios.yaml`, `categories.yaml`. Every holding must have a display name and a taxonomy entry; a bad edit stops the run with the exact ticker to fix.
1. **Data acquisition** — fetch EOD prices for the master ticker union (all modes + benchmarks + fund NAVs + bond and style proxies + sector ETFs); fetch S&P 500 history, VIX, Treasury yields, intraday bars; fetch Fama-French + Momentum factors and build the 8-factor ex-ante panel.
2. **Look-through expansion** — read `backend/data/active_fund_holdings.json`, replace each look-through mode's tickers + weights with its top-25 mappable holdings (re-normalized), and append the fund's own ticker as an unweighted reference row.
3. **Per-asset risk** — five VaR and five ES estimates, Hill tail index, EWMA-VaR percentile rank, monthly downside, 1-year VaR, and trailing exception count per ticker.
4. **Per-portfolio aggregation** — weighted return series through all five models, component VaR via EWMA covariance, risk trajectory.
5. **Positioning** — ex-ante positioning (§5.1), factor risk decomposition and bridge, AI and semis theme exposure, policy-benchmark comparison row.
6. **Scenarios** — historical replay over fixed windows (with long-history proxies for funds that post-date a crisis); hypothetical shocks resolved through the taxonomy, with per-holding assumption groups for the sliders.
7. **Backtesting** — Kupiec UC + Christoffersen IC for all five models per portfolio. GARCH/GJR results read from cache by default; regenerated with `RISKLENS_FULL_BACKTEST=1`.
8. **Performance** — risk-adjusted return, regime alpha, skill vs luck (computed; tab hidden).
9. **Market context** — S&P 500 per-year stats, cross-asset rolling correlation, multi-window stock-bond correlation across 4 bond proxies, intraday SPY-TLT correlation at 5m and 15m with the QMLE estimator alongside the naive one.
10. **Live signals** — Estrella-Trubin recession probability from the 10Y-3M Treasury spread.
11. **Sector Spotlight views** — per sector ETF: risk profile, beta vs SPY, Fama-French + Momentum regression, orthogonal cascade, thematic exposures, three detector time series (computed; tab hidden).

## 4. Data model — the JSON contract

The system's most important interface. Both the producer and the UI consumer treat this document as the source of truth. Feature additions are schema extensions, not sidecar API endpoints.

**Top level:**

```
{
  "generated_at":          ISO8601 UTC timestamp,
  "data_as_of":            "YYYY-MM-DD" — last US market close represented,
  "default_mode":          mode_id selected on initial render,
  "portfolios":            { mode_id: per-mode bundle },
  "sp500_history":         per-year aggregate stats (1928 onward),
  "correlation_history":   weekly samples of average pairwise correlation across a fixed basket,
  "multi_window_corr":     SPY × bond rolling correlations at 20d/60d/252d windows,
  "intraday_corr_history": 5m/15m intraday SPY-TLT correlation, last 60 trading days, naive + QMLE,
  "anomaly_views":         { tickers, names, data: { ticker: per-ticker bundle } }
}
```

**Per-mode bundle:**

```
{
  "label", "description",
  "weights":      { ticker: weight (sum to 1.0) },
  "assets":       [ ...per-asset rows..., portfolio summary row at end ],
  "benchmark":    policy-benchmark comparison row,
  "scenarios":    [ ...scenario records, type = historical | hypothetical; portfolio_pnl,
                    benchmark_pnl, active_pnl, and (historical, fund NAV) fund_pnl,
                    fund_active_pnl ],
  "risk_history": [ { date, var } ],
  "backtests":    [ ...one record per VaR model: exceptions, expected, kupiec_p,
                    christoffersen_p, verdict, eval_dates, violation_dates ],
  "exante":       ex-ante positioning (below),
  "theme_now":    AI and semis exposure: beyond-market beta, t-stat, tier, risk share,
                  shock translation, rolling beta,
  "factor_risk_decomposition": systematic vs specific split, per-holding and per-factor,
  "factor_risk_bridge":        change in modeled risk split into exposure / factor-vol / specific,
  "performance":  risk-adjusted return, regime alpha, skill vs luck (tab hidden),

  // Look-through modes only:
  "is_active_fund_spotlight": true,
  "fund_ticker":              "CGGO" | "AIVSX" | "RNPGX",
  "disclosed_weights":        { ticker: pct_of_fund },
  "coverage_meta":            { modeled_n, modeled_weight_pct, total_holdings, as_of },
  "fund_disclosure":          { fund_name, sponsor, mandate, as_of, n_holdings,
                                top10/top25 concentration, holdings: [...] }
}
```

**Ex-ante record (`exante`):**

```
{
  "model", "ewma_lambda", "ewma_halflife_days", "benchmark_label",
  "n_obs", "n_holdings", "first_date", "last_date",
  "active_risk_pct", "beta", "equity_beta", "equity_ref",
  "beta_market_factor", "active_beta", "active_beta_tstat",
  "style_gmv", "style_gmv_tstat", "style_label", "style_proxy",
  "style_active_hml", "style_hml_tstat",
  "total_risk_pct", "benchmark_risk_pct", "systematic_share_pct",
  "specific_share_pct", "model_capture_pct", "effective_n",
  "realized": { active_risk_pct, vol_pct, beta, corr, equity_beta },
  "fund":     { ticker, exante: {...same headline fields...}, realized: {...} } | null,
  "factors":  [ { factor, label, portfolio, benchmark, active, active_tstat,
                  significant, active_var_share_pct } ],
  "contributors": [ top 10 by risk share ],
  "notes":    [ plain-language limits ]
}
```

When `fund` is present, the UI headlines the fund's NAV-based numbers and shows the basket's as contrast.

**Per-asset row:** ticker, name, last_price, last_return_pct, var_hs/ewma/garch/tgarch/evt + es_*, monthly_p5, monthly_worst, var_yr_10pct, es_yr_10pct, tail_index, mean_var, risk_level, var_trend, exception_count, exception_rate, component_var.

The contract has held up across many rounds of feature additions (tabs, look-through baskets, factor models, ex-ante positioning, scenario sliders). A new computation maps to a new field on an existing record, a new subtree, or a new list under an existing record. The frontend treats unknown fields as no-ops and missing optional fields as feature-not-available, so producer and consumer can evolve at slightly different rates.

## 5. Methodology

### 5.1 Ex-ante positioning (`backend/exante.py`)

**Factor set (8).** Fama-French 5 + Momentum, plus two macro factors so multi-asset books get a real model:
- **DUR** — long-Treasury (TLT) excess return, orthogonalized to the equity market.
- **CRD** — high-yield minus long-Treasury (HYG − TLT), orthogonalized to market and DUR.

Orthogonalization keeps each loading interpretable on its own and stops the bond factors from absorbing variance that belongs to equity beta.

**Structure.** `Σ = B Σ_f Bᵀ + D` on a 252-day window. B comes from per-holding OLS on excess returns; D is each holding's residual variance.

**Covariance decay.** The factor covariance and residual variances are EWMA-weighted with a **126-trading-day half-life** (λ ≈ 0.9945), so predictions lean toward the current regime without swinging on one volatile fortnight. This is deliberately slower than the VaR engine's λ = 0.94 (~11-day half-life), which forecasts tomorrow rather than a year. Equal weighting would make predicted and realized nearly identical by construction.

**Active risk.** The active return series (portfolio − benchmark) is regressed directly on the factors:

```
TE = sqrt( aᵀ Σ_f a + active residual variance ) × sqrt(252)
```

Regressing the difference, rather than differencing two fitted exposures, measures the active residual instead of assuming portfolio and benchmark residuals are independent, and gives every active loading a standard error. Loadings with |t| < 1.96 are flagged insignificant and dimmed in the UI. The credit factor carries ~4% annualized volatility against the market's ~17%, so its loading is weakly identified and often insignificant.

**Beta.** Model-covariance beta against the benchmark, `Cov(p,b) / Var(b)`, which is what both risk systems and fund fact sheets mean by beta. The raw Mkt-RF loading is kept as a separate field; it is exposure to the US market factor, not to the portfolio's benchmark, and diverges sharply for global books. For multi-asset benchmarks the same model beta is also computed against ACWI (`equity_beta`), since beta to a 60/40 blend and beta to equities are different questions.

**Growth ↔ value.** Not read from the HML loading. Since the mid-2010s mega-cap growth is highly profitable, so profitability and momentum absorb much of what a PM means by "growth", and HML alone reads growth funds as neutral. Instead the active return is regressed on `[market, GMV]` where GMV = IWF − IWD (Russell 1000 Growth − Value), orthogonalized to market. A tilt is labeled only when |t| ≥ 2 **and** |loading| ≥ 0.05 (Strong at ≥ 0.15). Calibration on a trailing year: QQQ vs SPY ≈ +0.30, RPV vs SPY ≈ −0.64. GMV sits outside the 8-factor model because it is collinear with HML and momentum; it is used only for the label.

**Realized comparison.** Plain standard deviation of the active return, trailing regression beta, volatility, and correlation over the same window. Fund pages publish trailing 3- or 5-year monthly figures instead, so they differ on window and frequency.

**Fund-level block.** For look-through modes with a NAV series, the identical model is run on the fund's own returns. That answers "what is this fund's active risk"; the top-25 basket, re-normalized to 100%, is materially more concentrated and runs far higher (e.g. CGGO basket ~20% vs fund ~10%).

**Model capture** = model variance ÷ realized variance, so the size of the diagonal-D and 8-factor assumptions is visible. **Effective bets** = 1 / Σ(Euler risk share²) across holdings.

### 5.2 Factor risk decomposition and bridge (`backend/factor_models.py`)

`compute_factor_risk_decomposition` splits a basket's modeled variance into systematic `(Bᵀw)ᵀ Σ_f (Bᵀw)` and specific `Σ w_i² D_ii`, with Euler contributions per holding and per factor that sum exactly to their totals. FF5 + Momentum only (equity baskets), sample covariance.

`compute_factor_risk_bridge` attributes the change in modeled risk between two adjacent equal windows (weights held at the current disclosure) to three additive pieces: **exposure** (ΔB, style drift), **factor volatility** (ΔΣ_f, regime), and **specific** (ΔD). Sequential attribution; exact by construction. Ex-post explanation, not a forecast.

`compute_orthogonal_factor_cascade` sequentially orthogonalizes the six factors (Gram-Schmidt, fixed order) so R² decomposes additively. Order-dependent by design, and disclosed as such.

### 5.3 AI and semis exposure (`compute_theme_now`)

Two reads: **direct weight** in classified AI/semis names (null for pure ETF books; no pretending to see through an index), and a **return-based beyond-market beta** from regressing the portfolio on `[SPY, SMH ⟂ SPY]`. Also reports the theme's share of variance, a rolling 90-day beta, and a "SMH −20%" translation using the raw (non-orthogonalized) SMH beta, since a semis drawdown arrives with its usual market co-movement. Tiers: |β| ≥ 0.35 high, ≥ 0.15 elevated.

### 5.4 VaR and ES models

**Historical Simulation** — empirical p-th quantile of trailing 1,000 daily returns. At p = 0.01 the window holds 10 tail observations, the smallest count at which the empirical quantile is reasonably stable. ES is the average at or beyond VaR. No distribution assumption.

**EWMA** — RiskMetrics λ = 0.94. Recursion `var_t = (1−λ)·r²_{t−1} + λ·var_{t−1}`. Normal VaR and ES. Known fat-tail miss at 1%; the deliberate baseline.

**GARCH-t (1,1)** — Bollerslev conditional variance with **Student-t innovations**. Normal-innovation GARCH systematically understates 99% VaR by 30–60% on equity data. Student-t quantile with estimated ν; ES in closed form. Falls back to EWMA on non-convergence.

**GJR-t (1,1,1)** — adds the leverage term `γ·r²_{t−1}·I(r_{t−1}<0)`, still Student-t.

**EVT (Generalized Pareto)** — peaks-over-threshold above the 90th-percentile loss; VaR analytically from the GPD fit. Models the tail directly; tends toward conservatism, which is a feature for risk management and a calibration miss in formal backtests.

**Hill tail index** — α = k / Σ ln(L_i / L_k), k ≈ √n (min 10). Lower α = fatter tails.

**Monthly downside** — empirical 5th percentile and worst of rolling 21-day returns; no scaling assumption. **1-year VaR** — Student-t with σ scaled by √252, collapsed by default because √t scaling assumes iid returns.

**Component VaR** — `Component_i = w_i · (Σw)_i / σ_p · z · V` on the EWMA covariance. Sums exactly to portfolio EWMA VaR. Negative = hedge in the current regime.

### 5.5 Backtesting

Kupiec (1995) UC + Christoffersen (1998) IC on the book's full available out-of-sample history, with a strict 1,000-day lookback before each tested day. Directional verdict from the two p-values: CALIBRATED, UNDER-EST, OVER-CONSERV, CLUSTERED. All five models are tested. GARCH/GJR refits are warm-started from the previous converged parameters (3–10 iterations instead of 20–50) and cached at `backend/cache/garch_backtests.json`; the cache is keyed by mode, so a newly added mode needs one `RISKLENS_FULL_BACKTEST=1` run to get GARCH verdicts.

The Summary tab condenses verdicts to **Pass** (at least one model CALIBRATED), **Watch** (none calibrated, some CLUSTERED), or **Fail** (all under-estimate).

### 5.6 Stress

**Historical scenarios** (GFC, COVID, 2022 rate shock, Russia–Ukraine, Q4 2018) replay actual prices over fixed windows. Funds that post-date a crisis use configured long-history proxies; holdings with no usable proxy are excluded and the remaining weights re-normalized, with coverage % reported per scenario.

**Hypothetical scenarios** (Taiwan invasion, Iran/oil shock, US recession, AI bubble burst) are defined in `scenarios.yaml` as shocks **by asset class, region, and sector**, resolved to each holding through the `categories.yaml` taxonomy. Aggregation is linear, `Σ shock_i · w_i`, so contributions are exact and visible. Trade-off: the shock vectors encode an implicit correlation assumption rather than computing it.

**Assumption sliders.** Each hypothetical card groups holdings into assumption groups (tech & semis, US equities, intl developed, EM equities, rates & credit, gold & commodities, crypto). A slider multiplies every member's hand-set shock; the portfolio P&L recomputes client-side. The UI states plainly that this scales analyst assumptions and is not a factor model.

**Active stress P&L.** Every scenario is also run on the portfolio's benchmark weights, giving `benchmark_pnl` and `active_pnl` (portfolio − benchmark) per card. Where the fund's own price covers a historical window from its start (no mid-crisis launch, no proxy), the crisis is also replayed on the fund's NAV (`fund_pnl`, `fund_active_pnl`); look-through baskets overstate the gap, so the NAV figure is preferred when present.

**Recession probability** — Estrella-Trubin probit, `P = Φ(−0.5333 − 0.6330·spread)` on the 10Y − 3M spread, surfaced on the US Recession card.

### 5.7 Summary tab rules (`SummaryPanel.jsx`)

Each portfolio collects flags: active risk outside its **placeholder** tolerance band (index-based allocation 0.5–3%, active US 2–6%, active global 3–8%); |beta − 1| > 0.25; AI/semis tier high; VaR model check Watch or Fail; thin data (< 252 days of shared history, model capture < 70%, or no backtest). 0 flags = green, 1 = amber, 2+ = red. The stress column (largest `fund_active_pnl` or `active_pnl` across all scenarios) is context and does not set status. Bands, thresholds, and owner/action defaults are constants at the top of the file. Real bands would be set by the independent investment risk function with each PM.

### 5.8 Market context and hidden-tab methods

**Intraday correlation** — 5m and 15m SPY-TLT log-return correlation per day, last 60 days. Two estimators, toggleable: naive realized correlation, and **QMLE polarization** (Aït-Sahalia, Fan & Xiu 2010) `Cov(X,Y) = [IV(X+Y) − IV(X−Y)]/4` with Xiu (2010) univariate QMLE for each leg, which recovers latent correlation under microstructure noise.

**Fama-French + Momentum regression** (Sector Spotlight) — OLS on 252-day excess returns; loadings with t-stats, R², alpha, and vol decomposition.

**Anomaly detectors** (Sector Spotlight) — standardized z-score (|z| ≥ 3), two-sided Page CUSUM (k = 0.5, h = 5), and GJR-t GARCH-residual outliers (|z̃| ≥ 3).

**Performance & Skill** (`backend/performance.py`) — risk-adjusted return vs benchmark, alpha by market regime, and a skill-vs-luck test.

## 6. Look-through architecture

Active funds are modeled as look-through baskets of their top-25 disclosed holdings, with the fund's own NAV alongside:

1. **Sponsor disclosure** dropped into `ext-data/`:
   - Capital Group **ETFs** (CGGO): daily-holdings xlsx with tickers and weights.
   - Capital Group **mutual funds** (ICA, New Perspective): the quarterly "investment portfolio" Word export — the only export the fund page offers. Names, shares, and values, no tickers.
2. **`backend/preprocess_holdings.py`** routes by file extension. The Word reader parses tables from `word/document.xml`, derives weights as value ÷ total, strips footnote markers, and merges duplicate lines (e.g. a local listing and its ADR). Tickers come from a curated **per-fund name → ticker map** (`ICA_NAME_TICKERS`, `NPF_NAME_TICKERS`, selected by the registry's `name_map`). Map values use US symbols or ADRs where available (a USD-reporting fund's risk includes the currency move a local listing would miss), Bloomberg-style `SYMBOL XX`, or Korean A-prefix, all translated by `_map_to_yf_ticker`. Output: `backend/data/active_fund_holdings.json`, committed so CI never parses source files; the source files themselves stay local (gitignored).
3. **`run.py`** rewrites each look-through mode's tickers and weights to the top-25 mappable holdings re-normalized to 1.0, and appends the fund ticker as an unweighted reference row.
4. **Pipeline runs unchanged** on the basket. The ex-ante model additionally runs on the fund's NAV (§5.1), which becomes the Positioning and Summary headline.

**Share class.** Mutual funds use the lowest-fee class (R-6). Holdings are identical across classes and risk is effectively identical; fees would otherwise read as underperformance against the benchmark.

**Coverage.** Top-25 weight covers ~52% of CGGO, ~64% of ICA, ~46% of New Perspective. Coverage and the disclosure as-of date ship in the JSON and render on the Fund Holdings panel.

**History filter** in `compute_portfolio_row` — tickers with < 252 days of history are excluded from basket aggregation and weights re-normalized, so one recent listing doesn't collapse the basket's lookback.

## 7. Frontend rendering

Each tab owns a set of sections; each section is a self-contained component receiving a slice of the JSON.

- **Summary:** `SummaryPanel`.
- **Positioning:** `PositioningPanel`, `ThemeNowBanner`, `FactorRiskPanel`, `FactorRiskBridgePanel`.
- **Extreme Risk:** `RiskTable` (with `RiskBar`), `FundDisclosurePanel` (look-through modes), `PortfolioRiskChart`, `BacktestPanel` (with `CalendarHeatmap`).
- **Stress:** `ScenarioPanel`.
- **Market Context:** `HistoricalChart`, `CorrelationChart`, `MultiWindowCorrelationChart`, `IntradayCorrelationChart`.
- **Hidden:** `PerformancePanel`, `RegimeAlphaPanel`, `SkillLuckPanel`, `AnomalyDetectorPanel`, `OptimizerPanel`.

A reusable `Section` wrapper renders each section's title, plain-English question, a collapsible "About this section" description with curated literature references, and a collapse toggle persisted in `localStorage`. `InfoTip` and `HoverTip` handle tooltips (portaled and viewport-clamped).

Cross-component state is intentionally minimal: active tab and portfolio mode live in `App` and the URL; everything else is local to its section.

**Theme:** light "parchment" theme by default (warm cream ground, burnt-orange accent, JetBrains Mono), with a dark slate theme on a toggle persisted in `localStorage`. All colors are CSS tokens in `index.css`; Recharts components read resolved token values through `useThemeColors` so charts follow the theme.

## 8. Operational profile

Daily refresh runs unattended via GitHub Actions cron at 06:30 UTC weekdays.

**Observed failure modes:**
- yfinance occasionally returns malformed responses or drops a ticker (handled per ticker; a delisted holding is skipped with a warning).
- Yahoo throttling at high request volume (no observed impact at current volume).
- GARCH MLE occasionally fails to converge for high-vol assets (EWMA fallback).
- Ken French site maintenance (local CSV cache fallback at `backend/cache/ff_carhart_daily.csv`). The factor library also publishes with a lag of several weeks, so the ex-ante window ends at the latest factor date, not the latest price date.
- Recently listed international holdings with < 252 days of history (history filter).
- Configuration errors (a holding with no name or taxonomy entry) stop the run with the exact fix.

**Storage:** the JSON output is ~5.5 MB uncompressed, ~600 KB gzipped on the wire. The GARCH backtest cache is ~360 KB; the FF factor cache ~1.3 MB.

**Compute profile:** single machine, single process. CPU is single-threaded; embarrassingly parallel components are not parallelized because serial time is acceptable.

**Monitoring:** GitHub Actions job status, plus the `data_as_of` date in the header as a passive freshness signal.

No application server, no live database, no operational state outside the JSON output, the two caches, and the holdings JSON.

## 9. Scalability characteristics

**Per-asset risk** is O(N) in unique tickers, dominated by GARCH MLE (~0.5–1s per asset). Current N ≈ 130 (about 100 portfolio holdings across all modes, plus benchmarks, proxies, and sector ETFs). Embarrassingly parallel; `multiprocessing.Pool` would scale near-linearly.

**Per-portfolio computation** is O(P). Dominant costs are the rolling backtest (cached GARCH) and the ex-ante regressions (one OLS per holding plus the active and fund series). At P = 7 this fits comfortably in a daily window; at P = 100 it would benefit from parallelization.

**JSON size** grows with N·P and with the hidden-tab anomaly views. At ~5.5 MB it is past the point where splitting into per-portfolio and per-view JSONs with lazy loading would help first paint. The mode toggle and tab structure already map cleanly to lazy fetching, and the hidden-tab views could be dropped from the default build.

## 10. Risks and limitations

### Methodology limitations

**Ex-ante model scope.** Eight factors, not a commercial model's 40+: no industry, country, or currency factors, so concentrated industry or country bets land in residual risk and predicted active risk runs low. Exposures come from a trailing regression with weights held at current disclosure, so the model reprices only as the window rolls, where a characteristics-based model reprices the instant a trade settles. No covariance shrinkage and no forecast confidence bands.

**Look-through coverage.** Top-25 baskets cover 46–64% of the mutual funds. Factor and holding breakdowns describe the basket, not the whole fund; headline figures use fund NAV to compensate.

**Hypothetical scenarios** are specified by category, not propagated through factors. A factor-shock approach would reuse the same shock across any portfolio with the right loadings; the 8-factor model now exists, so wiring scenarios through it is well-scoped.

**Multi-period VaR** uses √t scaling for the 1-year figure and an empirical 21-day distribution for the monthly one. A rigorous multi-period model (overlapping-return fits or Monte Carlo paths) is not implemented.

**Historical replay coverage** falls for young holdings (e.g. New Perspective's 2008 replay covers ~73% of its basket).

### Data limitations

yfinance data can be delayed, incomplete, or inconsistently adjusted. Forward-filling short gaps is correct for EOD analysis only.

Mutual-fund holdings are quarterly with a lag. Name → ticker maps are curated per fund and need maintenance when new names enter the top 25; an unmapped name stays on the disclosure panel with no risk row.

The Treasury yield series used for the recession probability has occasional unit inconsistencies, corrected heuristically.

### Architectural and operational limitations

Single-document JSON, serial pipeline, no server-side rendering, no alerting beyond GitHub Actions failures, no audit logging, and no automated regression tests on the math. Each is a deliberate simplification at current scale; the mitigations (JSON split, a health-check monitor, a small unit-test suite over canonical inputs) are well-defined.

## 11. Alternatives considered

**Vendor risk systems (Bloomberg PORT, MSCI BarraOne, Axioma, Aladdin, FactSet)** — mature, factor-rich, regulator-trusted, far more comprehensive. Also expensive and opaque. RiskLens is complementary: a methodology-transparent layer that can sit alongside them.

**Open-source quant frameworks (QuantLib, Pyfolio, vectorbt)** — different scope: derivatives pricing, backtest analytics, and systematic strategies respectively.

**No-code BI tools (Tableau, PowerBI, Looker)** — visualization layers that cannot run their own Kupiec tests or fit GARCH-t.

**Server-side rendering and live data** — would need an app server, database, cache, and job queue. Not warranted without a sub-daily latency requirement.

**Database-backed data layer (Postgres, DuckDB, Parquet)** — natural at 10× scale; the §4 data model maps to it mechanically.

**Other chart libraries (D3, Plotly, Highcharts)** — more flexibility or heavier bundles or commercial licenses. Recharts has been adequate.

## 12. Open technical questions

**Richer factor model.** Adding industry and country factors (or a characteristics-based exposure model) would close the main gap in predicted active risk for concentrated books.

**Scenarios through factors.** Drive hypothetical shocks through the 8-factor loadings instead of category vectors.

**Full-holdings look-through.** SEC N-PORT filings give every US mutual fund's full holdings in machine-readable form (~60-day lag) with security identifiers, removing the top-25 limit and most of the manual mapping.

**Summary governance.** Real tolerance bands per mandate from the investment risk function; exception history over time; revenue-at-risk once AUM and fee data are available.

**Multi-period VaR**, **confidence bands on the risk trajectory**, **multivariate realized-kernel intraday covariance**, **active staleness alerting**, and **JSON splitting with lazy loading** remain open, as before.

## 14. Reproducing a daily run

```bash
git clone <repo>
cd risklens

# Backend
python -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.lock.txt

# Optional: regenerate holdings JSON after dropping new files in ext-data/
python backend/preprocess_holdings.py

# Regenerate everything else (writes frontend/public/data/risk_output.json)
python backend/run.py

# After adding a portfolio, or to refresh GARCH backtests (slow)
RISKLENS_FULL_BACKTEST=1 python backend/run.py

# Frontend
cd frontend
npm install
npm run dev      # http://localhost:5173
```

Production deploy is fully automated via the GitHub Actions workflow.
